# C++自定义算子注册

## 1. vLLM 算子注册的整体架构

### 核心注册文件
- **主注册文件**: `csrc/torch_bindings.cpp` - 包含 CUDA 算子
- **CPU注册文件**: `csrc/cpu/torch_bindings.cpp` - 包含 CPU 算子  
- **ROCm注册文件**: `csrc/rocm/torch_bindings.cpp` - 包含 ROCm 算子

## 2. 详细的注册流程

### 第一步：C++ 算子实现
算子的具体实现通常在相应的 `.cu` 或 `.cpp` 文件中，比如：
```cpp
// csrc/ops.h 中声明
void paged_attention_v1(
    torch::Tensor& out,
    torch::Tensor& query,
    torch::Tensor& key_cache,
    // ... 其他参数
);

// csrc/attention/paged_attention_v1.cu 中实现
void paged_attention_v1(...) {
    // 具体的CUDA kernel实现
}
```

### 第二步：使用 TORCH_LIBRARY_EXPAND 宏注册

在 `csrc/torch_bindings.cpp` 中使用 PyTorch 的注册宏：

```cpp
TORCH_LIBRARY_EXPAND(TORCH_EXTENSION_NAME, ops) {
  // 定义算子schema（函数签名）
  ops.def("paged_attention_v1("
          "    Tensor! out, Tensor query, Tensor key_cache,"
          "    Tensor value_cache, int num_kv_heads, float scale,"
          "    Tensor block_tables, Tensor seq_lens, int block_size,"
          "    int max_seq_len, Tensor? alibi_slopes, str kv_cache_dtype,"
          "    Tensor k_scale, Tensor v_scale, int tp_rank,"
          "    int blocksparse_local_blocks, int blocksparse_vert_stride,"
          "    int blocksparse_block_size, int blocksparse_head_sliding_step"
          ") -> ()");
  
  // 注册具体实现到CUDA设备
  ops.impl("paged_attention_v1", torch::kCUDA, &paged_attention_v1);
}
```

### 第三步：多设备支持的注册

vLLM 支持多种设备，每种设备有独立的注册：

```cpp
// CUDA 版本
TORCH_LIBRARY_EXPAND(TORCH_EXTENSION_NAME, ops) {
  ops.def("rms_norm(Tensor! out, Tensor input, Tensor weight, float epsilon) -> ()");
  ops.impl("rms_norm", torch::kCUDA, &rms_norm);
}

// CPU 版本  
TORCH_LIBRARY_EXPAND(CONCAT(TORCH_EXTENSION_NAME, _cpu), cpu_ops) {
  cpu_ops.def("mla_decode_kvcache(...) -> ()");
  cpu_ops.impl("mla_decode_kvcache", torch::kCPU, &mla_decode_kvcache);
}

// ROCm 版本
TORCH_LIBRARY_EXPAND(TORCH_EXTENSION_NAME, rocm_ops) {
  rocm_ops.def("LLMM1(Tensor in_a, Tensor in_b, int rows_per_block) -> Tensor");
  rocm_ops.impl("LLMM1", torch::kCUDA, &LLMM1);  // ROCm使用kCUDA标识
}
```

### 第四步：命名空间组织

vLLM 将算子组织到不同的命名空间中：

```cpp
// 主要算子：torch.ops._C.*
TORCH_LIBRARY_EXPAND(TORCH_EXTENSION_NAME, ops) { ... }

// 缓存操作：torch.ops._C_cache_ops.*  
TORCH_LIBRARY_EXPAND(CONCAT(TORCH_EXTENSION_NAME, _cache_ops), cache_ops) { ... }

// CUDA工具：torch.ops._C_cuda_utils.*
TORCH_LIBRARY_EXPAND(CONCAT(TORCH_EXTENSION_NAME, _cuda_utils), cuda_utils) { ... }

// 自定义AllReduce：torch.ops._C_custom_ar.*
TORCH_LIBRARY_EXPAND(CONCAT(TORCH_EXTENSION_NAME, _custom_ar), custom_ar) { ... }
```

### 第五步：Python 层包装

在 `vllm/_custom_ops.py` 中提供 Python 接口：

```python
def paged_attention_v1(
    out: torch.Tensor,
    query: torch.Tensor,
    key_cache: torch.Tensor,
    # ... 其他参数
) -> None:
    torch.ops._C.paged_attention_v1(
        out, query, key_cache, value_cache, num_kv_heads, scale, block_tables,
        seq_lens, block_size, max_seq_len, alibi_slopes, kv_cache_dtype,
        k_scale, v_scale, tp_rank, blocksparse_local_blocks,
        blocksparse_vert_stride, blocksparse_block_size,
        blocksparse_head_sliding_step)
```

## 3. 特殊的注册特性

### Meta函数注册（用于图模式）
对于返回 Tensor 的算子，还需要注册 meta 函数：

```cpp
if hasattr(torch.ops._C, "gptq_gemm"):
    @register_fake("_C::gptq_gemm")
    def _gptq_gemm_fake(a: torch.Tensor, b_q_weight: torch.Tensor,
                        # ... 参数
                       ) -> torch.Tensor:
        return torch.empty((a.size(0), b_q_weight.size(1)),
                           dtype=a.dtype,
                           device=a.device)
```

### 条件编译支持
某些算子只在特定条件下编译：

```cpp
#ifndef USE_ROCM
  // 只在非ROCm环境下编译
  ops.def("cutlass_scaled_mm(...) -> ()");
  ops.impl("cutlass_scaled_mm", torch::kCUDA, &cutlass_scaled_mm);
#endif
```

### Stride 标签支持
对于某些 GEMM 操作，需要特殊的 stride 处理：

```cpp
at::Tag stride_tag = at::Tag::needs_fixed_stride_order;

ops.def("cutlass_scaled_mm(...) -> ()", {stride_tag});
```

## 4. 编译和链接流程

### CMake 配置
通过 `define_gpu_extension_target` 宏定义扩展：

```cmake
define_gpu_extension_target(
    _C  # 扩展名称，对应 torch.ops._C
    DESTINATION vllm
    LANGUAGE ${VLLM_GPU_LANG}
    SOURCES ${VLLM_EXT_SRC}
    COMPILE_FLAGS ${VLLM_GPU_FLAGS}
    ARCHITECTURES ${VLLM_GPU_ARCHES}
    INCLUDE_DIRECTORIES ${VLLM_EXT_INCLUDE}
    USE_SABI 3
    WITH_SOABI
)
```

### 注册宏展开
`TORCH_EXTENSION_NAME` 最终展开为 `_C`，因此：
- `TORCH_LIBRARY_EXPAND(TORCH_EXTENSION_NAME, ops)` → `torch.ops._C`
- `TORCH_LIBRARY_EXPAND(CONCAT(TORCH_EXTENSION_NAME, _cache_ops), cache_ops)` → `torch.ops._C_cache_ops`

## 5. 运行时调用流程

1. **Python调用**: `vllm._custom_ops.paged_attention_v1(...)`
2. **PyTorch分发**: `torch.ops._C.paged_attention_v1(...)`  
3. **设备分发**: 根据tensor设备选择对应实现（CUDA/CPU/ROCm）
4. **C++执行**: 调用对应的C++函数实现

这种注册机制使得 vLLM 能够：
- 支持多种硬件后端
- 提供类型安全的算子调用
- 支持 PyTorch 的编译和图模式
- 保持良好的代码组织结构


# python侧自定义算子注册

vLLM中不少算子需要在运行时注册，如triton kernel，第三方插件中的算子，自由组合的算子等。vLLM为此创建了高效的注册方式。

## 注册函数
vllm.utils.register_custom_op

```python
# create a library to hold the custom op
vllm_lib = Library("vllm", "FRAGMENT")  # noqa


def direct_register_custom_op(
        op_name: str,
        op_func: Callable,
        mutates_args: list[str],
        fake_impl: Optional[Callable] = None,
        target_lib: Optional[Library] = None,
        dispatch_key: str = "CUDA",
        tags: tuple[torch.Tag, ...] = (),
):
    """
    `torch.library.custom_op` can have significant overhead because it
    needs to consider complicated dispatching logic. This function
    directly registers a custom op and dispatches it to the CUDA backend.
    See https://gist.github.com/youkaichao/ecbea9ec9fc79a45d2adce1784d7a9a5
    for more details.

    By default, the custom op is registered to the vLLM library. If you
    want to register it to a different library, you can pass the library
    object to the `target_lib` argument.

    IMPORTANT: the lifetime of the operator is tied to the lifetime of the
    library object. If you want to bind the operator to a different library,
    make sure the library object is alive when the operator is used.
    """
    # 兼容性检查
    if not supports_custom_op():
        from vllm.platforms import current_platform
        # 检查PyTorch版本是否支持custom_op (需要>=2.4)
        assert not current_platform.is_cuda_alike(), (
            "cuda platform needs torch>=2.4 to support custom op, "
            "chances are you are using an old version of pytorch "
            "or a custom build of pytorch. It is recommended to "
            "use vLLM in a fresh new environment and let it install "
            "the required dependencies.")
        return
    # Schema推断
    import torch.library
    if hasattr(torch.library, "infer_schema"):
        schema_str = torch.library.infer_schema(op_func,
                                                mutates_args=mutates_args)
    else:
        # for pytorch 2.4
        import torch._custom_op.impl
        schema_str = torch._custom_op.impl.infer_schema(op_func, mutates_args)
    
    # 操作注册
    my_lib = target_lib or vllm_lib
    my_lib.define(op_name + schema_str, tags=tags)
    my_lib.impl(op_name, op_func, dispatch_key=dispatch_key)
    if fake_impl is not None:
        my_lib._register_fake(op_name, fake_impl)
    # fake_impl是一个"假"的实现函数，它不执行真正的计算，而是：
    # 1. 推断输出张量的形状和数据类型
    # 2. 类型和设备推断
    # 3. 支持 torch.compile 和其他编译器
    # 当使用 torch.compile 时：
    # 追踪阶段：编译器使用 fake tensors（没有真实数据的张量）来追踪计算图
    # 形状推断：调用 fake_impl 来确定每个操作的输出形状和类型
    # 图优化：基于形状信息进行内存优化、算子融合等
    # 代码生成：生成优化后的执行代码
```

## 优势
- 性能优化：绕过复杂的分发逻辑，减少运行时开销
- 直接控制：可以精确控制操作注册到哪个后端
- 简化接口：提供了比标准PyTorch注册更简洁的API
- 编译友好：支持fake实现，便于与torch.compile等编译器集成
